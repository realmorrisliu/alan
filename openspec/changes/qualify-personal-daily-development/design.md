# Design

## Context

The original development qualification retains 21/30 first passes and 91 attempts;
Linux recovery remains assisted and delegation is unqualified. Main ea929481
contains the latest composer and dependency deliveries. See proposal.md for scope.

## Goals / Non-Goals

Qualify the user’s actual foreground macOS workflow. Do not equate a passing
fixture, full-trust bypass, root fallback or a complete checklist with general
unassisted self-development. Linux parity, background scheduling and automatic
input routing are not first-release gates.

## Decisions

Use a predeclared intake rubric and immutable task ledger, not hand-picked final
successes. Include small repairs, cross-file changes, check/build failure diagnosis,
read-only review and interrupted/resumed work. Record unavailable prerequisites
and rejected/abandoned tasks; do not remove started tasks from the denominator.

At least fifty independently verified tasks across two consecutive weeks and both
repositories must reach 90% completion without unplanned rescue. Ordinary initial
authorization and task clarification are separate from corrective advice, runtime
repair, manual bypass and operator-authored solutions. A model fixing its own
failure within budget is not human rescue; original attempt outcomes still remain.

Measure the default project-autonomous posture. Full-trust runs are a separate
cohort and cannot improve that score. Retain first-attempt outcomes separately
from task completion. Freeze numeric task limits, interruption counting rules,
family/repository mix and comparison subset before formal sampling; pilot data
cannot be retrospectively promoted to qualification. Candidate changes retain
old results and require reruns/applicability proof for affected outcomes.

Codex is the primary comparison with the same frozen task and repository snapshot.
Align model and effort where supported; otherwise mark whole-product comparison.
Report task completion, intervention, elapsed time and available usage separately.
Pi is supplemental. No fabricated normalized cost or relative speed threshold.

Use fresh installed/native CLI launches, ordinary Herdr input, actual resize and
scrollback interactions. A Ratatui buffer check complements but does not replace
physical-terminal acceptance. Review model-produced code independently.

## Risks / Trade-offs

- Cherry-picked success → freeze the intake rubric and preserve all starts.
- Two weeks is a finite observation → report sample limits, not a universal guarantee.
- New production changes invalidate evidence → pin source/binary and rerun affected cases.
- User work or website deployment is affected → isolated worktrees, no publication in the pilot.
- Measurement costs become the work → reuse retained evidence; keep collection bounded.

## Deferred measurements

Before formal qualification, freeze numeric execution/Tool/model budgets, a finite
pilot bound and reviewer evaluation thresholds in the owning change. These are
explicit gates, not authority for unlimited measurement. Capability and profile
selection must be recorded; historical gpt-6.1-sol/medium is a starting candidate,
not proof that every comparison supports it.

Eligibility and ordinary-task classification are fixed before task admission.
Every admitted failed, blocked, abandoned or budget-exhausted task remains in the
scored denominator. An unsupported prerequisite discovered after admission cannot
become a retrospective intake exclusion. Candidate reruns retain the original
candidate denominator and result ledger.
