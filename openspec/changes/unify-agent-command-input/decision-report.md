# 统一输入与原生命令执行：决策报告

状态：2026-09-24 用户批准的设计修订；运行时实现待完成。
ADR-0058 记录决策，当前 change 的 spec deltas 记录目标契约。本报告为解释性摘要。

## 一、结论

短期保留宿主原生运行方式。Alan 统一输入、Agent 状态与执行证据；成熟 shell
负责命令解释执行；alan9 命令封装内部控制；aP 留作内部服务和资源协议。
用户无需感知 aP，Agent 无需手写协议操作。复用已有 Host Mount 与 sandbox 边界。
暂不推进 Linux VM/容器迁移、FUSE、9P gateway、自研 shell 或 syscall 透明转换。

## 二、用户看到的行为

| 输入 | 行为 |
| --- | --- |
| `!git status` | 在共享执行 cwd 运行宿主命令，无需模型生成 |
| `!rg TODO src \| head` | 管道按选定宿主 shell 的语义执行，权限仍受约束 |
| `:解释刚才的输出` | Agent 使用同一份命令证据回答，也可按授权调用工具 |
| `!cd subdir` | 独立 cd 成功后，按队列顺序改变共享 cwd |
| `!cd subdir && make` | 整个脚本执行；cd 只影响本次脚本 |
| 无前缀输入 | 第一阶段继续走 Agent；自动分类通过独立资格验证后启用 |

提示符直接表达这一条输入的意图：

```text
alan: 帮我看看测试为什么失败
alan! cargo test
alan: 解释一下刚才的报错
```

默认 `alan: `；空输入键入 `!` 后变成 `alan! `，正文不重复显示前缀。
命令正文为空时按退格返回对话；提交被接受后下一条恢复 `alan: `，失败则保留草稿。
空输入粘贴 `!git status` 同样生效；已有正文中插入的 `!` 是文字。
显式 `:` 仍强制 Agent 路由，不重复显示冒号；历史恢复保留原意图。
回答已有确认/表单时，前缀字符保持答案文字，不触发普通输入路由。
这只是规范输入的呈现，实际权限与执行仍由运行时处理。
未来自动分类需要先设计并验证可见路由，不能在 `alan: ` 表示对话时静默执行命令。

一个多行输入是一次提交、一个 shell 脚本，不拆成多个独立排队任务。
`!` 不增加权限；命令失败不自动交给模型修复。脚本可能已有部分效果，不能宣称回滚。

独立 cd 首版只支持一个可引号/转义的字面目录参数；空参数、`-`、`~`、变量及
替换表达式明确报错。这是共享目录更新的有限 builtin，不扩展为 shell 解释器。
export、alias、function 和脚本内部状态不自动延续到下一次命令。

## 三、用户不感知 aP：项目文件统一，内部控制封装

| 使用面 | 对外体验 | 内部实现 |
| --- | --- | --- |
| 项目文件 | Agent 编辑、shell、外部编辑器使用同一份文件与一致路径 | Host adapter 校验授权并解析到已有 HostFS/aP 或原生文件操作 |
| Alan 内部控制 | Agent 调用面向任务的 alan9 命令；高级用户也可显式调用 | 命令封装已有服务的 aP 操作、提交与错误处理 |
| 普通宿主命令 | 保留真实 shell 的 PATH、文件和脚本语义 | 统一执行入口与 sandbox |

例如：用户要求更新 README → Agent 编辑并成功保存 → 用户 `!git diff` 看见修改 →
Agent 继续解释或处理结果。反过来，用户在外部编辑器保存的修改也应被后续 Agent 读取。
待保存 buffer 必须明确标记；不能把尚未写入项目文件的修改宣称为已保存。

Agent 的 read/edit/search 使用与 shell 一致的公开项目路径。映射仅发生在明确的
结构化路径参数边界，继续验证挂载授权；不扫描、替换任意 shell 脚本。
本地挂载对应已授权宿主文件；记忆、Agent 状态等虚拟资源不需要变成宿主文件。
`/mnt` 拓扑是内部资源组织，既不自动进入 prompt，也不作为普通用户必学概念。

alan9 命令主要供 Agent 使用，但不是秘密或特权后门。通过现有 executable/Tool
元数据发现能力，提供任务参数、结果和错误，内部复用服务所有者。首批只封装真实任务
需要的操作，具体命令名和 schema 随实现明确，不为每个 aP 文件操作造一个命令。
普通 `cat`、`q` 仍按宿主查找规则工作；只有显式安装和调用的控制命令提供 Alan 能力。
不要求用户知道 `/proc/clone`、fid、clunk 或自己拼接控制文档。

命令文本保持原样。输出保留真实含义并执行既有脱敏规则；不能把后续命令需要使用的
宿主路径改成不可用的内部别名。开发者仍可检查内部协议和文件树。

## 四、授权与执行流程

```text
用户 ! / Agent 工具请求
        ↓
Agent Machine：排序、当前 cwd、取消与结果关联
        ↓
现有原生 Tool Process 执行入口：策略、审批与证据
        ↓
Host adapter：委托 grant → 原生 cwd/环境/sandbox
        ↓
宿主 shell 与子进程 → 输出、退出码、Action 证据
```

Host Mount Service 继续拥有授权。一个显式委托 grant 同时支持 HostFS 与原生命令权限。
虚拟挂载不授予宿主访问权限；知道路径或 grant ID 也不授予权限。
alan9 命令连接内部服务时使用调用者委托的能力，不借用权限更大的环境连接。
能够启动一个原生程序不意味着有权控制所有内部服务。命令返回需区分“任务已接受”
和“任务已完成”；提交结果未知时不自动重复执行。

Host adapter 仅在 adapter 自身的原生 spawn 与 sandbox 边界解析并使用宿主 cwd/path，
不将其写入 Alan Process exec manifest。AgentFS、
Machine state、Agent 可见结果与 durable evidence 延续现有 Host 路径保密和脱敏合同，
保存公开项目路径或 opaque grant reference，不保存 backing root。逻辑挂载申请、grant
和服务审计仍保持逻辑记录；不暴露未委托目录或虚拟服务私有存储。Engine 不维护另一份
sandbox 根清单。

Linux 现有 reified sandbox 要保留命令所需的原生路径身份，无需把脚本翻译到 /mnt。
macOS/Linux 都保留既有 sandbox 和降级策略；不因透传而绕过审批或扩大权限。
现有后端能力有限时必须如实报告；不把路径字符串检查宣称为任意程序的完整隔离。

## 五、状态所有权

- Agent Process：共享 cwd 的 Host Mount 引用与相对位置。
- Agent Machine：提交顺序、命令/Agent 路由、队列暂停状态。
- Host adapter：原生路径解析、sandbox 和原生子进程管理。
- AgentFS 与 rollout/checkpoint：现有可观察状态和持久执行证据。
- TUI：展示与输入；不拥有第二个 executor、cwd 或执行队列。

每个 shell 子进程不自动变成一个独立 Alan Process。取消仍需要覆盖本次行动的原生
后代进程，并区分已完成效果、取消成功和未知状态。Ctrl-C 暂停剩余队列；detach 不取消。
重启不自动重放未知效果；恢复 cwd 时重新检查 grant 和目录可用性，不悄悄换目录。

## 六、最小交付与验证

1. 复用原生执行适配器，接通显式 `!`/`:`；无前缀维持 Agent 基线。
2. 验证命令不被改写：管道、引号、重定向、多行、PATH、部分失败与真实退出码。
3. 验证路径与授权：同一 grant 的 aP/native 访问、只读限制、越界/符号链接、虚拟目录、
   启动前撤销、后端降级。输出路径不能误导下一次命令。
4. 验证共享状态：独立 cd、脚本内 cd、两个客户端排队、取消后代、重启不重放。
5. 验证 alan9 命令封装、权限拒绝、提交错误及结果未知；正常用户流程与命令帮助无需协议知识。
6. 验证 Agent 编辑 → git diff、外部编辑 → Agent 读取，以及未保存/冲突/只读/越界行为。
7. 完成 macOS/Linux 边界验证与既有质量门槛后交付。自动分类继续独立推进。
