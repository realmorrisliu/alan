01 · ARCHITECTURE

Built like an operating system, not a chat wrapper.

Ordinary processes

Agent-ness is a file-layout convention, never a second Kernel Process type. owns lifecycle truth; projects its live view.

Explicit boundaries

Launching alan never exposes your host directory. Host Mounts, Skills (), and Host Store credentials stay strictly separated.

Terminal-first

No Electron shell or sidebar. Run interactively inside modern terminal hosts like Herdr, or pipe tasks cleanly through stdin and stdout.

02 · STANDARD NAMESPACE

          

            Seven directories. Zero hidden globals.
          


          

            
              

                
                Process table and lifecycle truth — PID, descriptors, credentials, and exit state.
              

              

                
                AgentFS views served by the Agent Runtime Service, with /agent/root for the root process.
              

              

                
                Service Handle Registry — rendezvous tree for mountable aP file-server handles.
              

              

                
                Reusable Tools and Agent Executables, including Quartermaster at /bin/q.
              

              

                
                Immutable Skill package content projected at /lib/pkg/<id> on explicit reference.
              

              

                
                Manual pages for commands, file servers, and architectural conventions.
              

              

                
                Explicitly authorized Host Mounts. Host directories never leak in implicitly.
              

            
          


          

            Quartermaster (/bin/q) installs Skills strictly from authorized namespace paths
            (q install --name my-skills /mnt/import/my-skills) — never raw host paths or hidden URLs.
